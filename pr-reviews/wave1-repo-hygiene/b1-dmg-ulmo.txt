# macOS arm64 (macOS 27.0.1). Branch wave1/repo-hygiene 8382c4ff.
# Input: ReShiki.app from the released reshiki-0.15.0-macos-arm64.zip.
# A small driver stages the folder exactly as mac_disk_image() does (ReShiki.app,
# Applications -> /Applications, Install ReShiki.txt), then calls
# scripts/installers.py create_disk_image(staging, "ReShiki-ULMO.dmg") with every run() command echoed.
# It then runs main's command (hdiutil create -format UDZO) on the same staged folder for the size comparison.
# Temporary folders are shown as $TMPDIR/ReShiki disk image XXXX; hdiutil convert's per-partition
# "Reading ..." lines are left out.

## create_disk_image: UDZO into a temporary folder, then hdiutil convert to ULMO
$ ditto reshiki-0.15.0-macos-arm64/ReShiki.app '$TMPDIR/ReShiki disk image XXXX/contents/ReShiki.app'
$ hdiutil create -volname ReShiki -srcfolder '$TMPDIR/ReShiki disk image XXXX/contents' -format UDZO -ov '$TMPDIR/ReShiki disk image XXXX/zlib.dmg'

## Why not hdiutil create -format ULMO directly (the first version of this branch)
# On macOS 27.0.1 arm64, hdiutil create -srcfolder ... -format ULMO failed with
# "hdiutil: create failed - No space left on device" for the 0.15.0 app alone (6 of 6 attempts)
# and for the app with only the Applications link (8 of 8). The release layout passed 8 of 8.
# UDZO never failed. The failure depends on folder contents, so retries do not help.
